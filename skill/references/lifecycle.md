# 约定生命周期（v0.2.6：核心逻辑）

## 状态机

```
持有中 ──证伪触发（价格事件）──→ 待复盘 ──用户复盘──→ 已归档
                               └── 7天未回应 ──→ 已归档（标注"未复盘"）
持有中 ──复盘日到达──→ 持有中（提醒事件，状态不变）
持有中 ──复盘提醒后7天未回应──→ 已归档（标注"未复盘"）
持有中 ⇄ 接近证伪线（≤3% 预警进入，价格回到预警线外退出）
接近证伪线 ──证伪触发──→ 待复盘
持有中 ──用户复盘回应──→ 已归档
持有中 ──用户主动停止──→ 已停止 ──24h内撤回──→ 持有中
                       └── 超24h ──→ 已归档（结束语=轻量复盘）
持有中 ──用户修订──→ 持有中（版本+1，v1原文永存）
任何状态 ──用户删除──→ 墓碑
```

## 核心规则

1. **append-only**：时间线只追加不修改。修订=加新版本，原文 v1 永存。这是"防反悔"的技术底座。
2. **停止三件套**：停止时间、当时价格、结束方式，agent 自动记；再追问一句"留句结束语吗"（不阻塞）。结束语=该约定的轻量复盘。
3. **删除**：提交时即告知 append-only＋墓碑（规则写在前面）。"删了我那条"→确认是哪条→即删即走，不问为什么、不挽留；内容清、墓碑留。建错 24h 内撤回不留墓碑。用户明确要求连墓碑一起删→照办，但声明"这段历史彻底空白了"（用户指令压过 skill 条款，减速带非墙）。
4. **回收=引用**：约定不可复活；新建同标的约定时 agent 主动递回历史摘要（≤3 行：旧证伪线、结局、结束时间）。停错 24h 内撤回停止，超 24h 走新建＋引用。
5. **口头豁免无效**（铁律第 7 条）：破线后"再等等"必须落成修订（新版本＋原话保留）；agent 固定回复："'再等等'我记不下来——要改就走修订：你说，我记成新版本。"
6. **修订 vs 新建边界**：改证伪价/条件/日期=修订（版本+1）；换标的、反方向、旧约定终结后重新建=新建（引用旧的）。
7. **提醒记回应状态**：每次提醒记"已提醒（已回应/未回应）"，复盘时可递回（"这条线我提醒过你 X 次"）。
8. **复盘日只产生提醒**：复盘日到达是提醒事件，不产生状态迁移。状态迁移只能由用户回应（复盘/修订/停止/删除）或价格事件（证伪触发）产生。时间观见 `references/time.md`。

## 固定文案

- 提交时告知："约定进入时间线，只追加不修改。删内容可以，会留一条墓碑。"
- 停止追问："停了。留句结束语吗？（不回也行）"
- 删除执行："删了。时间线留了一条墓碑。"
- 引用摘要："你 X 月 X 日那条[标的]，证伪线 X，结局[……]——这次证伪线还定 X 吗？"
- "再等等"回复："'再等等'我记不下来——要改就走修订：你说，我记成新版本。"

## 记录字段

id、标的、方向、证伪线、证伪条件原文（v1 verbatim）、提交时间、提交时价格、复盘锚（事件＋偏移）、时间尺{距上次核对交易日数、距提交自然日数、提醒次数、未回应次数}、状态、版本历史[]、事件时间线[]、结束{时间/方式/价格/结束语}、复盘结论、墓碑标记。
